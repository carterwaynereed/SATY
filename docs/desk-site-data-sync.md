## Each scheduled update

1. Obtain SPY one-minute candles from `get_ticker_candles_by_range` (`range:1m, interval:5d, end_interval:0d`). Obtain SPY daily history (`get_ticker_ohlc_latest_or_date`, limit 60) once per Eastern date or when missing. Inspect actual tool errors, delay notices and structured results. Do not request AAPL/GOOGL for entry signals. Retain SPX entitlement failure; retry that access at most once per trading day.
2. Save an update in `data/provider-update.json` with `{symbol:"SPY",retrievedAt,bars,delayed,notices,daily?}`. `retrievedAt` is the actual time the provider call returned, never the later disk-write time. For an initialized history, read the latest stored SPY bar end before fetching. Transfer only returned rows ending at or after ten minutes before that timestamp, plus all rows with invalid timestamps, and set `incremental:true`. This keeps small overlapping revisions and all new bars while preserving warm-up history locally. For startup, transfer the full returned history. Include original candle fields without repairing or inventing rows. An error update contains `error` and `retrievedAt` and retains previous bars. Keep credentials out of this file. Large result arrays may be transferred in bounded chunks to an ignored temporary file, then atomically renamed after complete JSON parsing.
3. Run `node ingest.mjs data/provider-update.json`, then `node scan.mjs` during active trading windows or `node scan.mjs --no-auto-paper` for preparation/reviews. All entries remain underlying-direction paper studies. Save failures and do not soften WAIT gates. Check `data/site-sync-status.json` after uploading.
4. Call Sites `get_site` with the exact project ID and verify the expected Site origin. Obtain the returned `siwc_bypass_bearer_token` in memory. Do not print or store it. Public audience is expected and is not permission to write journal records: the current helper derives the separately configured journal service credential. If access is unavailable or the API denies authorization, stop the upload and report the blocker. Never change access policy or bypass the private API guards to make an upload succeed.
5. Start `node sync-site.mjs` with a retained PTY. At its hidden-input ready message, send one JSON line `{site:"https://saty-plus-trading-desk.zestyfawn9.chatgpt.site",token:<returned token>}` through structured stdin, not a shell argument. The helper uses only this Site, refuses redirects, uploads to `/api/update`, reads `/api/snapshot` back and checks the saved timestamp. This writes data only; do not rebuild or republish for routine scans.
6. Record a sync failure without marking the website current. No automatic retries for access failures. For an uncertain response, read the saved timestamp before retrying. Hosted writes reject older timestamps and concurrent overwrites.

## Readiness and limits

The browser shows feed age, calendar status and the latest successful upload. Stale data (>90 seconds) remains WAIT even if the website refresh succeeds. A five-minute heartbeat necessarily has stale gaps and can miss fast scalps. No options premiums or option profitability are inferred. Existing baseline formulas and risk limits are unchanged. Imported snapshots remain an optional offline backup.

The journal updater uses the existing task's authorized UW tools and the protected Sites service writer; it does not claim direct hosted UW connector consent or a streaming connection. Runtime authorization key names and rotation requirements are documented in [hosting/README.md](../hosting/README.md). The optional owner sign-in reads the journal; it does not authorize browser writes.
